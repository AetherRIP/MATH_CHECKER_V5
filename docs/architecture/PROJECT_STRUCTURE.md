# Project structure and cleanup policy

Math Checker V5 — production Edexcel IGCSE 4MA1 correction system. This file is
the map of the repository: what every top-level folder is for, which folders are
shipped, which are disposable, and what was reorganised on 2026-10-12.

## Root — entry points, manifests and runtime docs

The launcher-visible files and the two documents referenced directly by runtime
code stay in the root; developer-facing reports and guides live under `docs/`.
The maintained starting documents are [README.md](../README.md) and
[ARCHITECTURE.md](ARCHITECTURE.md). Historical reports are retained as an audit
trail, and may describe older builds or older test counts.

```
MATH V5/

  remote.py               public/LAN remote-access helper started by start_public.bat (shipped)
```

## Shipped vs. not shipped

The release pipeline is **allowlist-first**
(`MathChecker_Distribution/scripts/release_allowlist.py`, plus the independent
blocking scan `scan_release.py`):

* **Shipped:** `main.py`, `remote.py`, `start.bat`, `start.sh`,
  `start_public.bat`, `README.md`, `backend/requirements.txt`, the `.py`/`.sql`
  files under `backend/app`, the `.py` files under `agent/`, and the built
  `frontend/dist` bundle.
* **Never shipped:** `docs/`, `dev_local/`, `data/`, `autostart/`,
  `backend/tests/`, `backend/scripts/`, everything with a credential-looking name,
  databases, PDFs, logs and caches. Adding a new top-level folder does **not**
  ship it — only an explicit allowlist entry would.

## Data, generated files and what must never be tidied away

| Category | Location | Handling |
|---|---|---|
| Active source | `backend/app/`, `frontend/src/`, `agent/`, `main.py`, `remote.py` | Modify deliberately; keep runtime resource paths stable |
| Configuration templates | `MathChecker_Distribution/documentation/config.toml.example`, `MathChecker_Distribution/documentation/` | Sanitized defaults and recipient guidance; never put live secrets here |
| Dependencies | `backend/requirements.txt` (runtime only), `backend/requirements-dev.txt` (tests), `frontend/package.json` and `frontend/package-lock.json` | Preserve declared dependency behavior and lockfile reproducibility; never add test-only packages to the runtime file |
| Regression tests | `backend/tests/`, `frontend/tests/` | Keep mocked/synthetic; don't copy student data into fixtures. The Dashboard browser fixture (`backend/scripts/seed_dashboard_fixture.py`) writes synthetic rows into a throwaway `MC5_DATA_DIR` and refuses a directory that already holds a real `app.db`. Scratch data directories are created through `backend/tests/tempdirs.py`, which registers them and deletes them at session end (closing the log/database handles first — Windows refuses to delete an open file), and reports any directory it could not remove |
| Runtime/persistent data | `data/`, `autostart/` | Preserve; user-specific and never source cleanup targets. The `data/` folder is this checkout's; an installed copy resolves its own folder through `backend/app/data_location.py` (`%LOCALAPPDATA%\MathChecker`, never the system temp directory) |
| Generated UI | `frontend/dist/` | Rebuild from source; git-ignored and required to run this checkout |
| Release artifacts | `MathChecker_Distribution/build/`, `release_staging/`, `portable/`, `release/` | Generated/replaced by the release pipeline; current contents are ignored by source allowlisting and must be audited before sharing. Only `release/` (the hand-off ZIP/installer) and `build/` (the bundled runtime the pipeline consumes) are kept in git; `release_staging/` and `portable/` are git-ignored working copies |
| Release history | `MathChecker_Distribution/previous_builds/` | Rollback material and the baseline `backend/scripts/release_update_check.py` compares against. Keep at most the newest package; the folder is git-ignored so future packages stay out of history (`docs/size_optimization/README.md`). The one package tracked at `HEAD` is unaffected by that rule until it is deleted |
| Dev scratch/evidence | `dev_local/`, `docs/logs/` (ignored), `docs/results/`, `docs/evidence/` | Keep separate from active source; review privacy before sharing or deleting. `docs/results/` contains redacted verification output; `docs/logs/` is local-only |
| Caches | `__pycache__/`, `.pytest_cache/`, `frontend/tsconfig.tsbuildinfo` | Regenerable and ignored; safe to remove when tools are not using them |


* `data/` — the real application data: `app.db` (+ rolling backups),
  `config.toml`, `secrets.toml`, `secrets/`, `blueprints/`, `mark_schemes/`,
  `logs/`, `fixtures/`, `retained/`. It is the app's working database and the
  teacher's configuration; **no cleanup step touches it**.
  This folder is the *source checkout's* data root: `backend/app/data_location.py`
  resolves `MC5_DATA_DIR` first, then data beside the app (portable copy or an
  existing installation), then a `.git` checkout's `data/`, and otherwise the
  platform's per-user folder — `%LOCALAPPDATA%\MathChecker` on Windows. Data an
  older layout left in the temp folder (or beside the app before the per-user
  default) is **copied** into that folder on the next start, with
  `migration.json` recording the source; the original is never moved or
  modified. `python main.py --adopt-data <folder>` does the same on demand.
  `data/secrets/` is the canonical home for credentials, including
  `google_oauth_client.json` / `client_secret_*.json` (auto-detected by
  `backend/app/config.py`).
* `autostart/` — machine-local autostart scripts, logs and `service_install.json`
  written by `scripts/install_autostart.py` and read by the app
  (`backend/app/main.py`, `public_access.py`, `distributed/tiny_agent.py`). It is
  runtime state, so it stays where the code expects it.
* `.venv/` and `.venv.foreign/` — Python environments. `.venv.foreign` is not
  junk: `setup.bat` moves a foreign-platform environment there **instead of
  deleting it** (documented in README.md). Both are excluded from the release.
* `Friend code/` — **removed on 2026-10-15 at the owner's request.** The friend's
  original Streamlit app used to live here as the untouched reference
  implementation. Nothing in the running app ever read it: the correction engine
  was already preserved verbatim in `backend/app/engine/legacy_marking.py`, and
  `LEGACY_APP_DIR` in `backend/app/config.py` was dead code. The only consumer was
  a dev-only comparison script that has since been removed along with the
  one-off audit tooling. The release scanner still deny-lists the name, so a
  restored copy could never be shipped.

## dev_local/ — development scratch and preserved audit material

This folder is excluded from releases. It contains report previews and harness
runs, but also archived release audit copies (`release_audit_backup/`) and other
historical data. Do **not** interpret its name or ignore status as permission to
delete the whole tree; inspect individual contents first. See
`dev_local/README.md` where available.

```
dev_local/reports/        PDF/PNG renders from backend/scripts/pdf_preview.py
dev_local/runs/           scratch data dirs of local e2e harnesses
dev_local/archive/        superseded dev data (probe dumps, throwaway test DBs)
```

## MathChecker_Distribution/ — packaging workspace

See [MathChecker_Distribution/README.md](../../MathChecker_Distribution/README.md).
`build/`, `release_staging/`, `portable/` and `release/` are live pipeline
folders; `build_release.py` cleans/replaces staging, portable and release, while
`build_runtime.py` can replace the bundled runtime under `build/`. `logs/` keeps
pipeline output, and `previous_builds/` keeps superseded packages under an
explicit retention policy. These directories are expensive and destructive to
recreate: do not run a release build during cleanup without first checking which
local artifacts need to be retained and the script's backup/retention behavior.

## Cleanup policy

1. **Regenerable → generally disposable:** `__pycache__/`, `.pytest_cache/`,
   `*.pyc`, `frontend/tsconfig.tsbuildinfo`. Scratch under `dev_local/` is
   excluded from releases, but inspect it first: the directory includes
   preserved release-audit copies and may include valuable evidence.
2. **Superseded output → keep one generation:** previous portable builds go to
   `MathChecker_Distribution/previous_builds/<date>/`; keep at most the two most
   recent, delete older ones deliberately (they are multi-hundred-MB folders).
3. **Runtime state → never tidy:** `data/`, `autostart/`, the venvs.
4. **Uncertain → keep and document,** never delete. Historical material that is
   still useful is listed in [docs/README.md](../README.md) with the reason it was
   kept.
5. **Logs** go to the git-ignored `docs/logs/` (development) or
   `MathChecker_Distribution/logs/` (packaging). The running app's own logs stay
   in `data/logs/`. Verification transcripts must be checked for student data
   before they are shared or copied anywhere else.

## What the 2026-10-12 reorganisation changed

* 14 root reports + 2 result JSONs + 7 logs + the audit evidence folder moved
  into `docs/`; every cross-link inside them was rewritten to the new depth.
* `.probe/`, `data_e2e/`, the stale `backend/data*` scratch databases and the
  root `reports/` preview output moved under `dev_local/`.
* `_dist_backup/original_20261012/` (an earlier portable build) moved to
  `MathChecker_Distribution/previous_builds/`.
* The three `MathChecker_Distribution/*.log` pipeline logs moved to
  `MathChecker_Distribution/logs/`.
* The loose `client_secret_*.json` moved into its documented canonical home,
  `data/secrets/` (resolution re-verified through
  `config.resolve_oauth_client_path()`).
* `backend/bin/show-canonical-after-recompute.py` joined the other one-off
  scripts in `backend/scripts/`.
* Scripts that wrote into the project root were pointed at their new homes
  (`dev_local/reports`, `dev_local/runs`, `docs/results`).
* Caches and the TypeScript build stamp were removed; `.gitignore` gained
  `dev_local/` and `.live_verify/`.

This historical note records that the 2026-10-12 reorganisation removed only
regenerable caches and the empty `backend/bin` directory. The full `mv` receipt
was a local log; version control is the authority for later changes. Review the
current diff before reverting or repeating cleanup.
